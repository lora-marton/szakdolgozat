preprocessor.py — Line-by-Line Explanation
============================================

This file is the preprocessing orchestrator for the dance comparison pipeline.
It synchronises two dance sequences temporally (via audio cross-correlation)
and trims them to their shared active region before DTW alignment runs.


Lines 1–9: Module Docstring
-----------------------------
Describes the file's purpose and lists the four preprocessing steps:
1. Audio cross-correlation to find the frame offset between two videos.
2. Apply offset — shift/trim the leading video so both start at the same beat.
3. Motion energy detection — find the active dance range in each sequence.
4. Intersection — keep only the overlapping active region.


Lines 10–15: Imports
---------------------
- numpy (as np): Array operations — used in _slice_data() to detect and slice
  numpy arrays vs scalar metadata.
- DEFAULT_PREPROCESSOR_CONFIG (from model.config): The default PreprocessorConfig
  instance, used as fallback when no config is passed to preprocess().
- PreprocessorConfig (from model.config.preprocessor_config): The type itself,
  used in the type annotation for the config parameter.
- compute_audio_offset (from model.preprocessing.audio_sync): Extracts audio
  from both videos and returns the lag in frames via cross-correlation.
- compute_motion_energy, find_active_range (from model.preprocessing.motion_energy):
  Compute per-frame motion energy from landmarks and find the start/end of the
  active dance region by thresholding.


Lines 18–19: Preprocessor Class
---------------------------------
- A class that groups all preprocessing logic as static methods.
- Contains no instance state — all methods are @staticmethod.
- One public method (preprocess) and two private helpers (_apply_offset, _slice_data).


Lines 21–28: preprocess() Signature
--------------------------------------
- @staticmethod: No self parameter, called as Preprocessor.preprocess().
- Parameters:
    - teacher_data (dict): Dict with 'landmarks', 'masks', 'trajectory' numpy
      arrays plus scalar metadata like 'fps' and 'fixed_scale'.
    - student_data (dict): Same structure as teacher_data.
    - teacher_video (str): Path to the teacher video file (for audio extraction).
    - student_video (str): Path to the student video file (for audio extraction).
    - config (PreprocessorConfig | None): Optional configuration. If None,
      DEFAULT_PREPROCESSOR_CONFIG is used.
- Returns: tuple[dict, dict, dict] — the trimmed teacher_data, student_data,
  and a preprocess_info dict with offset metadata.


Lines 44–45: Default Config Fallback
--------------------------------------
- If no config was passed, use DEFAULT_PREPROCESSOR_CONFIG with all standard
  thresholds (audio_sample_rate=22050, motion_threshold_ratio=0.15, etc.).


Line 47: FPS Extraction
-------------------------
- Reads the frame rate from teacher_data. Defaults to 60.0 if not present.
  This fps is passed to compute_audio_offset() so the audio lag in seconds
  can be converted to a frame count.


Lines 49–55: Step 1 — Audio Cross-Correlation
------------------------------------------------
- Calls compute_audio_offset() with both video paths, the target fps, and the
  audio sample rate from config.
- Returns an integer offset: positive means teacher leads (started earlier),
  negative means student leads, zero means in sync.
- Prints the offset and a human-readable description of which video leads.


Lines 57–58: Audio Trim Tracking
----------------------------------
- Records how many frames will be trimmed from each video due to audio offset.
  teacher_audio_trim is nonzero when teacher leads (offset > 0).
  student_audio_trim is nonzero when student leads (offset < 0).
  These values feed into preprocess_info so downstream code knows where the
  trimmed data starts relative to the original HDF5 sequences.


Line 60: Step 2 — Apply Offset
---------------------------------
- Calls _apply_offset() which trims leading frames from the earlier video
  and truncates both to the same length. After this call, both sequences
  start at the same musical moment.


Lines 62–73: Step 3 — Motion Energy Detection
------------------------------------------------
- Computes per-frame motion energy for both sequences using landmark displacement.
- Calls find_active_range() on each energy array to find the start and end frames
  where the dancer is actively moving (above the threshold ratio, for at least
  min_active_duration consecutive frames).
- Prints the active range for each dancer.


Lines 75–89: Step 4 — Intersection
-------------------------------------
- Computes the shared active region as the intersection of both active ranges:
  shared_start = max(t_start, s_start), shared_end = min(t_end, s_end).
- If shared_start >= shared_end, there is no overlap — prints a warning and
  returns the data as-is with only audio offset info in preprocess_info.
- Otherwise, prints the shared region size and slices both datasets to it.


Lines 91–100: Final Slicing and Return
----------------------------------------
- Slices both teacher and student data to [shared_start:shared_end].
- Builds the preprocess_info dict with:
    - audio_offset: Raw frame offset from audio cross-correlation.
    - teacher_offset: Total frames trimmed from start of teacher's original
      HDF5 data (audio trim + shared region trim).
    - student_offset: Same for the student.
  These offsets are used by the feedback video renderer to sync the overlay
  back to the correct frames in the original videos.
- Returns the trimmed (teacher_data, student_data, preprocess_info) tuple.


Lines 102–132: _apply_offset() — Private Static Method
---------------------------------------------------------
- Takes both data dicts and the audio offset.
- If offset > 0 (teacher leads): trims the first `offset` frames from teacher.
- If offset < 0 (student leads): trims the first `|offset|` frames from student.
- After trimming the leader, truncates both to the shorter sequence length
  so they have the same number of frames.
- Returns the trimmed (teacher_data, student_data) tuple.


Lines 134–155: _slice_data() — Private Static Method
-------------------------------------------------------
- Generic helper that creates a shallow copy of a data dict with all numpy
  arrays sliced to [start:end].
- Non-array entries (e.g. 'fps', 'fixed_scale') are preserved unchanged.
- The end parameter accepts None (meaning "slice to the end"), which is used
  by _apply_offset() when trimming only the leading frames.
- Returns the new dict with sliced arrays and preserved scalars.
