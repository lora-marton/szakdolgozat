trajectory_metrics.py — Trajectory Comparison Metrics
======================================================

This file compares how the teacher and student move across the floor by
analysing their hip-center trajectory. It breaks movement into two
components: direction (where are they going?) and speed (how fast?).

The trajectory data comes from the extraction phase, where each frame's
hip-center position (midpoint of landmarks 23 and 24) is recorded as an
(x, y) coordinate in normalized [0, 1] space.


================================================================================
Function ordering and visibility
================================================================================

  compute_trajectory_score   public    Orchestrator — called from comparator.py
  _direction_similarity      private   Per-frame cosine similarity of velocity
  _speed_similarity          private   Per-frame min/max speed ratio


================================================================================
compute_trajectory_score — orchestrator
================================================================================

Purpose: Single entry point for trajectory comparison. Takes DTW-aligned
teacher/student hip positions and returns a combined score plus direction
similarity for feedback.

Input:
  - teacher_trajectory: shape (N, 2) — hip-center (x, y) per aligned frame.
  - student_trajectory: shape (N, 2) — same shape, same alignment.
  - weight_direction: how much direction matters (default 0.75).
  - weight_speed: how much speed matters (default 0.25).
  - min_speed_threshold: noise floor for movement detection (1e-4).

Output:
  Dict with:
    - 'score': combined trajectory score (0-100).
    - 'direction_similarity': raw direction metric (0-1) for feedback.

Step by step:

  1. Compute velocity vectors:
       teacher_vel = np.diff(teacher_trajectory, axis=0)

     np.diff computes the difference between consecutive elements along
     the given axis. For shape (N, 2), this gives (N-1, 2) — one 2D
     displacement vector per frame transition. Each vector (dx, dy)
     represents how far and in what direction the dancer moved between
     frame t and frame t+1.

  2. Compute scalar speeds:
       teacher_speed = np.linalg.norm(teacher_vel, axis=-1)

     Euclidean length of each velocity vector: sqrt(dx² + dy²). This
     gives "how many coordinate units did the dancer move" regardless
     of direction. Shape (N-1,).

  3. Filter active frames:
       active = (teacher_speed > threshold) | (student_speed > threshold)

     Frames where BOTH dancers are nearly stationary (below 1e-4) are
     excluded. When neither is moving, comparing their tiny jittery
     displacements would give meaningless direction scores. If at least
     one dancer is moving, the frame is kept — a moving teacher with a
     stationary student should be penalized.

     If no frames are active (both stationary the entire time), return
     a perfect score of 100.0 and direction similarity of 1.0.

  4. Compute direction similarity on active frames via _direction_similarity.

  5. Compute speed similarity on active frames via _speed_similarity.

  6. Weighted combination:
       score = (0.75 * mean_direction + 0.25 * mean_speed) * 100

     Direction is weighted 3× more than speed because moving in the
     right direction matters more than matching speed exactly. A student
     who moves the right way but a bit slowly is doing better than one
     who moves fast in the wrong direction.

  The direction_similarity is returned separately (not just as part of
  the score) so the feedback system can tell the student specifically
  whether their direction or speed needs improvement.


================================================================================
_direction_similarity
================================================================================

Purpose: Measure whether two dancers are moving in the same direction,
independent of how fast they move.

Input:
  - teacher_vel, student_vel: shape (M, 2) — velocity vectors (active only).
  - teacher_speed, student_speed: shape (M,) — pre-computed magnitudes.

Output:
  - similarity: shape (M,) — per-frame scores in [0, 1].

Step by step:

  1. Compute dot product per frame:
       dot = (teacher_vel * student_vel).sum(axis=-1)

     Element-wise multiply gives (M, 2), summing the last axis collapses
     to (M,). This is the same dot product formula used in joint angle
     computation: a·b = ax*bx + ay*by.

  2. Compute denominator:
       denom = teacher_speed * student_speed

     Product of magnitudes. This is the normalization factor that turns
     the dot product into a cosine:
       cos(θ) = (a · b) / (|a| * |b|)

  3. Handle stationary frames:
       both_moving = denom > 0
       cosine[both_moving] = dot[both_moving] / denom[both_moving]

     Where one dancer is stationary (speed = 0), the denominator is 0.
     Instead of dividing by zero, cosine stays at 0.0. This penalizes
     the frame — if the teacher is moving and the student is still (or
     vice versa), direction similarity is 0.

     Note: these frames passed the active filter (at least one is moving),
     so one-stationary frames are intentionally scored as bad.

  4. Map cosine from [-1, 1] to [0, 1]:
       similarity = (cosine + 1.0) / 2.0

     Raw cosine similarity ranges from -1 (opposite directions) to +1
     (same direction). This linear mapping shifts it to [0, 1]:
       Same direction      → cosine = +1.0 → similarity = 1.0
       Perpendicular        → cosine =  0.0 → similarity = 0.5
       Opposite direction   → cosine = -1.0 → similarity = 0.0

     The 0.5 for perpendicular movement is a design choice — moving at
     90° to the teacher is "half right" (not as bad as going backwards,
     not as good as going the right way).


================================================================================
_speed_similarity
================================================================================

Purpose: Measure whether two dancers move at the same speed, independent
of direction.

Input:
  - teacher_speed, student_speed: shape (M,) — magnitudes (active only).

Output:
  - ratio: shape (M,) — per-frame scores in [0, 1].

Step by step:

  1. Compute element-wise max and min:
       max_speed = np.maximum(teacher_speed, student_speed)
       min_speed = np.minimum(teacher_speed, student_speed)

     np.maximum / np.minimum operate element-wise (not to be confused
     with np.max / np.min which reduce an array to a single value).

  2. Compute ratio with zero guard:
       ratio[nonzero] = min_speed[nonzero] / max_speed[nonzero]

     Where max_speed > 0, the ratio is min/max. Where both are zero,
     ratio stays 0.0 (though this shouldn't occur since active frames
     have at least one dancer moving).

     The min/max ratio is a symmetrical similarity measure:
       Both move at 5 units    → 5/5 = 1.0  (perfect match)
       One at 10, other at 5   → 5/10 = 0.5 (half speed)
       One at 10, other at 1   → 1/10 = 0.1 (very mismatched)
       One moving, other still → 0/10 = 0.0 (complete mismatch)

     This is the same ratio approach used by the mask energy comparison
     in mask_metrics.py.


================================================================================
How this fits into comparator.py
================================================================================

Comparator calls a single method:

  trajectory_result = TrajectoryMetrics.compute_trajectory_score(
      aligned_teacher_traj, aligned_student_traj,
      weight_direction=config.trajectory_weight_direction,
      weight_speed=config.trajectory_weight_speed,
  )

Results accessed via dict keys:

  trajectory_result['score']                  → combined 0-100 score
  trajectory_result['direction_similarity']   → raw 0-1 for feedback

The trajectory score feeds into the final weighted overall score:

  overall = 0.55 * skeleton + 0.15 * trajectory + 0.30 * mask

Trajectory has the lowest weight (15%) because it captures gross floor
movement, not detailed pose accuracy. A dancer can be in roughly the
right spot but have poor arm positions — skeleton comparison catches that.
Conversely, a dancer with perfect poses but consistently wrong positioning
would lose points here.


================================================================================
Config parameters used (from ComparisonConfig)
================================================================================

  trajectory_weight_direction = 0.75    Direction sub-score weight
  trajectory_weight_speed = 0.25        Speed sub-score weight
  weight_trajectory = 0.15              Trajectory weight in overall score
