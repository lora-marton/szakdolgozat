mask_metrics.py — Mask-Based Comparison Metrics
=================================================

This file compares dancer silhouettes (segmentation masks) between teacher
and student. It has a 3-stage pipeline:

  Stage 1: EFD contour smoothing — clean up noisy mask edges
  Stage 2: DTM shape scoring — measure silhouette overlap
  Stage 3: Optical flow energy — measure movement similarity

The public entry point is compute_mask_score, which orchestrates all three
stages and returns a combined score.


================================================================================
Function ordering and visibility
================================================================================

  compute_mask_score      public    Orchestrator — calls stages 1+2 and 3
  _smooth_mask_efd        private   Stage 1 — EFD contour smoothing
  _compare_shapes_dtm     private   Stage 2 — bidirectional DTM shape scoring
  _dtm_one_direction      private   Helper — single-direction DTM scoring
  _compare_mask_energy    private   Stage 3 — optical flow energy comparison
  _compute_frame_energy   private   Helper — flow magnitude for one frame pair

All functions called only within this file are private (prefixed with _).
Only compute_mask_score is called from comparator.py.


================================================================================
Stage 1: _smooth_mask_efd — Elliptic Fourier Descriptor smoothing
================================================================================

Purpose: Remove clothing noise, hair flyaways, and finger details from
segmentation masks, keeping only the gross body shape.

Input: A single-frame segmentation mask (H, W), uint8 0-255.
Output: A clean binary mask (H, W), uint8 0 or 255.

Step by step:

  1. Binarize the mask:
       binary = (mask > threshold).astype(np.uint8) * 255

     The input comes from MediaPipe segmentation — grayscale where higher
     values mean higher confidence that the pixel belongs to the person.
     Thresholding at 128 gives a hard yes/no decision. The result must be
     uint8 with values 0 or 255 because OpenCV's contour finder expects that.

  2. Find contours:
       cv2.findContours(binary, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_NONE)

     cv2.findContours traces the boundaries of white regions in a binary
     image. It walks along boundary pixels and returns them as ordered
     point sequences.

     cv2.RETR_EXTERNAL — only return outermost contours. Holes inside the
     dancer (gaps between arm and body) are ignored. We only want the
     outer silhouette.

     cv2.CHAIN_APPROX_NONE — store every single boundary pixel without
     compression. The alternative (CHAIN_APPROX_SIMPLE) would compress
     straight segments into just endpoints, but EFD needs dense point
     sampling to decompose accurately.

     Returns a list of contours, each shaped (M, 1, 2), and a hierarchy
     array that we discard.

  3. Select the largest contour:
       largest = max(contours, key=cv2.contourArea)

     cv2.contourArea computes enclosed area using the shoelace formula
     (sum of cross products of consecutive edge vectors). The largest
     contour is the dancer. Smaller contours are noise or background
     artifacts.

  4. Minimum points guard:
       if len(largest) < 10: return zeros

     EFD decomposition needs enough sample points to compute meaningful
     harmonics. With fewer than 10 points the contour is degenerate.

  5. Reshape for pyefd:
       contour_points = largest.squeeze()    → shape (M, 2)

     OpenCV contours have a vestigial middle dimension (M, 1, 2) from
     legacy API design. squeeze() removes it so each row is (x, y).

  6. EFD decomposition:
       coeffs = elliptic_fourier_descriptors(contour_points, order=n_harmonics, normalize=False)

     pyefd.elliptic_fourier_descriptors decomposes a closed 2D contour
     into a sum of ellipses rotating at integer frequencies — the 2D
     equivalent of a Fourier transform.

     How it works:
       - The contour is parameterized as two 1D signals: x(t) and y(t),
         where t goes from 0 to 2π around the contour.
       - Each signal is decomposed into cosine and sine components at
         increasing frequencies (harmonics).
       - Harmonic 1 captures the overall elliptical shape of the body.
       - Harmonic 2 adds refinement (roughly: head/legs distinction).
       - Higher harmonics capture finer detail (arms, clothing folds).
       - Each harmonic produces 4 coefficients: (a_n, b_n) for x(t)
         and (c_n, d_n) for y(t).

     order=n_harmonics (default 8) keeps only the first 8 harmonics.
     Returns shape (8, 4). This discards all high-frequency detail.

     normalize=False preserves the actual size, rotation, and orientation
     of the contour. This is important because we want to compare shapes
     at their real scale — a crouching student should have a different
     shaped mask than a standing teacher. (The follow-cam normalization
     in FrameProcessor already handles gross scale differences; remaining
     size/tilt differences are meaningful pose information.)

  7. Compute centroid:
       cx = contour_points[:, 0].mean()
       cy = contour_points[:, 1].mean()

     Arithmetic mean of all x and y coordinates. This is the geometric
     center of the original contour, needed to position the reconstructed
     curve in the correct location in the image.

  8. Reconstruct smoothed contour:
       reconstruct_contour(coeffs, locus=(cx, cy), num_points=n_points)

     pyefd.reconstruct_contour evaluates the Fourier series at n_points
     (200) evenly spaced values of t from 0 to 2π. The result is a smooth
     (200, 2) array of (x, y) points forming a closed curve. Since we
     only gave it 8 harmonics, all high-frequency jaggedness is gone.

     locus=(cx, cy) shifts the curve to the original contour's center.

  9. Fill the smoothed contour back into a binary mask:
       smoothed_int = smoothed_contour.astype(np.int32).reshape(-1, 1, 2)
       cv2.fillPoly(result, [smoothed_int], 255)

     Convert float coordinates to integer pixels, reshape back to OpenCV's
     (M, 1, 2) format, and fill the interior with 255.

     cv2.fillPoly draws a filled polygon — every pixel inside the smooth
     outline becomes 255, everything outside stays 0.


================================================================================
Stage 2: _compare_shapes_dtm — Distance Transform Mapping
================================================================================

Purpose: Measure how well two dancer silhouettes overlap, with graceful
partial-credit for near-misses.

Input: Two mask sequences (N, H, W) after DTW alignment.
Output: Mean score (0-1) and per-frame scores array.

The scoring uses a bidirectional approach — it checks both:
  Forward:  do student pixels fall inside the teacher shape?
  Backward: do teacher pixels fall inside the student shape?

This catches all mismatch types (shift, size difference, shape difference).

Per-frame loop:

  1. Smooth both masks through _smooth_mask_efd (Stage 1).

  2. Convert to boolean:
       t_binary = t_smooth > 0
       s_binary = s_smooth > 0

  3. Edge cases:
       Both empty → score 1.0 (trivial match, neither dancer visible)
       One empty  → score 0.0 (complete mismatch)

  4. Bidirectional DTM scoring:
       forward  = _dtm_one_direction(teacher → student)
       backward = _dtm_one_direction(student → teacher)
       score = (forward + backward) / 2

  5. After the loop, average only the active frames (skip both-empty).


_dtm_one_direction helper:

  This scores how well "query" pixels fall inside the "reference" shape.

  1. Compute distance transform on the INVERTED reference mask:
       outside_dist = distance_transform_edt(~reference_binary)

     scipy.ndimage.distance_transform_edt computes, for each non-zero
     pixel, the Euclidean distance to the nearest zero pixel.

     By inverting the reference mask (~reference_binary), the non-zero
     pixels are now OUTSIDE the reference shape. So the function computes,
     for each outside pixel, its distance to the nearest edge of the
     reference shape. Inside pixels are zero (they ARE the zero elements).

     Result:
       Inside reference  → 0 (these are background in the inverted mask)
       On reference edge  → ~1 (just barely outside)
       Far outside        → large distance

  2. Apply Gaussian decay:
       score_map = exp(-(outside_dist²) / (2σ²))

     This creates a smooth score map:
       Inside reference:        dist=0  → score = 1.0
       Just outside edge:       dist~1  → score ≈ 1.0
       σ pixels outside:        dist=σ  → score ≈ 0.61
       Far outside:             large   → score → 0

     With σ = 25 pixels (from config.dtm_sigma):
       25px outside edge → score ≈ 0.61
       50px outside      → score ≈ 0.14
       75px outside      → score ≈ 0.01

  3. Sample the score map at query pixel positions:
       score_map[query_binary].mean()

     Average the score map values at every pixel where the query mask
     is active. If all query pixels are inside the reference → mean ≈ 1.0.
     If query pixels are shifted or mismatched → lower mean.

  Why bidirectional:

    Forward only (teacher as reference, sample at student pixels):
      Student perfectly inside teacher but much smaller → scores 1.0
      This misses the fact that the student's shape is wrong.

    Backward only (student as reference, sample at teacher pixels):
      Student much larger than teacher, fully containing it → scores 1.0
      This misses that the student has excess area.

    Bidirectional (average of both):
      Perfect overlap:            forward=1.0, backward=1.0 → 1.0
      Student shifted slightly:   both drop    → medium score
      Student too small:          forward=1.0, backward drops → medium
      Student too large:          forward drops, backward=1.0 → medium
      Completely misaligned:      both ≈ 0     → ≈ 0

  This is essentially a soft bidirectional Chamfer distance — a standard
  technique in shape matching literature.


================================================================================
Stage 3: _compare_mask_energy — Optical Flow Energy
================================================================================

Purpose: Compare how much movement is happening in each dancer's
silhouette between consecutive frames.

Input: Two mask sequences (N, H, W).
Output: Dict with energy_score (0-1) and per-frame detail arrays.

_compute_frame_energy helper (per frame pair):

  1. Compute dense optical flow between consecutive mask frames:
       cv2.calcOpticalFlowFarneback(mask_prev, mask_curr, ...)

     cv2.calcOpticalFlowFarneback computes dense optical flow — for every
     pixel in the image, it estimates a displacement vector (dx, dy)
     describing how that pixel moved between the two frames.

     The algorithm (Farneback 2003) works by:
       a) Approximating each pixel's local neighborhood with a quadratic
          polynomial (a 2D surface fit).
       b) Computing how that polynomial must shift between frames to
          minimize the intensity difference.
       c) Iterating at multiple image pyramid scales to capture both
          large and small motions.

     Parameters:
       pyr_scale=0.5  — each pyramid level is half the previous size
       levels=3       — 3 pyramid levels (full, half, quarter resolution).
                        Coarse levels catch large motions, fine levels
                        refine small motions.
       winsize=15     — local neighborhood size for polynomial fitting.
                        Larger = smoother flow but less spatial detail.
       iterations=3   — refinement iterations per pyramid level.
       poly_n=5       — 5x5 neighborhood for polynomial expansion.
       poly_sigma=1.2 — Gaussian smoothing of the polynomial neighborhood.
       flags=0        — no special options.

     Returns shape (H, W, 2) — a 2D displacement vector per pixel.

  2. Compute flow magnitude:
       magnitude = np.linalg.norm(flow, axis=-1)    → shape (H, W)

     The Euclidean length of each displacement vector: sqrt(dx² + dy²).
     This gives "how many pixels did this point move" regardless of
     direction.

  3. Mask to the active region:
       region = (mask_prev > threshold) | (mask_curr > threshold)

     Union of both frames' mask regions. The union is needed because
     movement happens between the departure position (previous frame)
     and the arrival position (current frame). Using only one frame's
     mask would miss half the motion.

  4. Return mean magnitude inside the mask region.

_compare_mask_energy (per-pair scoring):

  For each consecutive frame pair (i, i+1):

  1. Compute energy for teacher and student separately.

  2. Score as min/max ratio:
       ratio = min(teacher, student) / max(teacher, student)

     This is a symmetrical similarity measure:
       Both move equally    → ratio = 1.0
       One moves 2x more    → ratio = 0.5
       One still, other not → ratio = 0.0
       Both still           → treated as 1.0 (trivial match)

  3. Aggregate: average the ratios across frames where at least one
     dancer was moving. Both-stationary frames are excluded to avoid
     inflating the score.


================================================================================
Known limitations of the energy comparison
================================================================================

  1. Flow is computed on mask images, not original video frames.

     The masks are mostly binary (0 or 255 interior). Optical flow relies
     on intensity gradients to track pixel motion, but the mask interior
     has no texture — it's uniform white. Flow can only track motion at
     the mask EDGES where there's a sharp 0/255 transition.

     This means the energy metric measures "how much did the silhouette
     boundary move" rather than "how did the body move within the
     silhouette." A movement that changes the outline a lot (spreading
     arms) registers as high energy, while a movement that barely changes
     the outline (rotating in place) registers as low energy even if
     there's significant actual motion.

     A more accurate approach would compute flow on the actual video
     frames (which have rich texture from clothing, skin, etc.), but
     those frames are not currently stored after extraction. This would
     require changes to the extraction pipeline to save downscaled
     grayscale frames in HDF5.

  2. The min/max ratio is direction-blind.

     The ratio only compares the MAGNITUDE of movement, not where or in
     what direction the dancers move. If the teacher moves their left arm
     fast and the student moves their right leg equally fast, the energy
     ratio would be 1.0 (perfect match) even though the movements are
     completely different.

     This is acceptable because the skeleton comparison (joint angles)
     already handles joint-specific movement differences. The energy
     metric adds a coarse "are they moving at similar intensity?" signal.

  3. Impact is limited by weighting.

     Energy is weighted at 30% of the mask score, and the mask score
     itself is 30% of the overall score. So energy contributes only
     0.30 × 0.30 = 9% of the final score. The direction-blind and
     edge-only limitations have limited impact on the overall assessment.


================================================================================
compute_mask_score — orchestrator
================================================================================

  1. Calls _compare_shapes_dtm (which internally calls _smooth_mask_efd)
     → dtm_score (0-1)

  2. Calls _compare_mask_energy
     → energy_score (0-1)

  3. Weighted combination:
       combined = (0.70 * dtm_score + 0.30 * energy_score) * 100

     Shape (DTM) is weighted higher because it directly measures pose
     similarity through silhouette overlap. Energy is a supplementary
     signal about movement intensity.

     The × 100 converts from 0-1 to 0-100 scale to match skeleton and
     trajectory scores.

  4. Returns a dict with the combined score plus per-frame details for
     the feedback system (per_frame_shape array and energy_details dict).


================================================================================
Config parameters used (from ComparisonConfig)
================================================================================

  mask_binary_threshold = 128    Binarization cutoff for mask pixels
  efd_harmonics = 6              Number of EFD harmonics (body shape detail)

  dtm_sigma = 25.0               Gaussian decay width in pixels for DTM
  flow_winsize = 15              Farneback optical flow window size
  weight_shape = 0.70            DTM shape weight in combined score
  weight_energy = 0.30           Energy weight in combined score
